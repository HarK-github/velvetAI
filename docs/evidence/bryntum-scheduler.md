## 3. Authoritative Read Model (`GET /v1/merchant/schedule`)

- **Route**: `apps/api/src/routes/schedule.ts`
- **Application Service**: `packages/application/src/schedule-service.ts` (`ScheduleService.getSchedule`)
- **Contract Schema**: `packages/contracts/src/schedule.ts` (`scheduleResponseSchema`)
- **Behavior**:
  - Single atomic read-only PostgreSQL transaction using `withTenantTransaction`.
  - Emits 4 resources for the judge tenant:
    1. Aria (Stylist) — Staff
    2. Marco (Barber) — Staff
    3. Lena (Therapist) — Room / Therapist
    4. Studio A (Room) — Room
  - Aggregates events across bookings, active unexpired holds, and seeded demo fixtures (`DEMO_FIXTURE`).
  - Pure payment state derivation (`toSchedulePaymentState`) mapping deposit states to `AWAITING_PAYER`, `VERIFYING`, `PAID`, `REFUNDED`, or `NONE`.
  - Privacy masking (`maskBuyerLabel`): formats names as `Guest <Initial>.<Initial>` or `Demo guest <N>`. Zero email addresses (`@`), zero phone numbers, and zero internal notes exposed.
  - Deterministic revision hash (`canonicalHash`) emitted as `scheduleRevision` and HTTP `ETag`. Supports conditional HTTP polling via `If-None-Match` returning `304 Not Modified`.
  - Query window enforcement: maximum 14-day window (`400 Bad Request` if exceeded).
  - Public demo mode: unauthenticated callers access `PUBLIC_DEMO_TENANT_ID` (the judge tenant) with 60 requests/minute/IP rate limiting; tenant overrides rejected with `400`.

## 4. Bryntum Scheduler Day View UI (`/schedule`)

- **Component**: `apps/web/src/pages/SchedulePage.tsx`
- **Render Helpers**: `apps/web/src/lib/schedule-render.ts`
- **Styling**: `apps/web/src/styles/bryntum-overrides.css`
- **Features Implemented**:
  - `<BryntumScheduler readOnly={true} ... />` configured for day view in merchant time zone (`America/New_York`).
  - Status-specific visual styling:
    - `HOLD`: dashed border, amber background, live 1-second countdown badge. Expired holds drop off locally immediately without waiting for server poll.
    - `AWAITING_DEPOSIT`: warm amber border + badge.
    - `VERIFYING_PAYMENT`: purple border with pulsing spinner indicator.
    - `PAID`: solid velvet emerald styling.
    - `CHECKED_IN`: teal styling with pin icon.
    - `COMPLETED`: neutral slate styling with check icon.
    - `NO_SHOW`: crimson outline styling.
    - `CANCELLED`: muted strike-through styling.
    - `DEMO_FIXTURE`: subtle dotted underline with "Demo booking" label.
  - Accessible `<ul>` legend below the scheduler documenting all 9 status indicators.
  - Navigation toolbar with `Today`, `← Prev Day`, `Next Day →`, merchant date display, and `"Updated N s ago"` indicator.
  - 5-second polling loop with `If-None-Match` header. Automatically pauses polling when browser tab is hidden (`document.visibilityState === 'hidden'`) and resumes on tab focus.
  - Screen reader announcements: `aria-live="polite"` container announces new confirmed bookings.
  - Public demo mode notice: signed-out visitors see `"Demo schedule (read-only). Sign in to book or run the race test."`.

## 5. Judge Race Test (`POST /v1/judge/race-test`)

- **Route**: `apps/api/src/routes/judge-race.ts`
- **Service**: `packages/application/src/judge/race-test-service.ts` (`JudgeRaceTestService`)
- **Shared Race Helper**: `executeConcurrentHoldRace` reused by both Race Test and Abuse Lab Runner (`L1`).
- **Features**:
  - Protected by `judge:abuse_lab` scope and restricted to the judge tenant.
  - Rate limited to 1 execution per 30 seconds (`429 RateLimitError`).
  - Fires $N=20$ concurrent hold attempts across parallel workers against production `BookingService.prepareBooking`.
  - PostgreSQL row-level advisory locking ensures exactly 1 hold succeeds, while 19 are rejected with `409 slot_unavailable`.
  - Automatic cleanup: winner is immediately released via `prepareCancellation` and `commitCancellation` so the schedule has zero test residue.
  - UI integration: Judge users have a `"Run race test (20 holds)"` button on the schedule page that triggers the test, reports summary `"20 simultaneous attempts → 1 hold, 19 rejected by the database"`, and flashes the winning slot.
